# Speech In Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Say "Hey Jarvis" and a French command to a satellite; the hub transcribes it, runs it through the assistant for real, and speaks the reply on that satellite while the room's music is held.

**Architecture:** The board (stock ESPHome + one C++ include) streams its mic over authenticated UDP to the hub only inside a window opened by the wake word or by the hub's "listen". The hub (`crates/nidoo/src/assist/stt/`) runs Silero VAD + Parakeet (sherpa-onnx), drives one small state machine per satellite, calls `Hub::assist` with client `satellite:<sid>`, and speaks the reply through the existing speak path. nidoo-sound gains a **hold** (music silenced on chosen players, speech still mixed) and reports the instant a sentence finished playing, plus each satellite's IPv4 address so the hub can greet the boards.

**Tech Stack:** Rust 2024; hub: axum, tokio UDP, `sherpa-onnx =2.0.1` (feature `stt`), `hmac 0.12` + `sha2 0.10`, `tar 0.4` + `bzip2 0.5`; nidoo-sound: tokio, rumqttc; web: Leptos (wasm) with wasm-bindgen-test; board: ESPHome 2026.10.2, mbedtls HMAC.

**Spec:** `docs/superpowers/specs/2026-11-04-speech-in-design.md` (approved 2026-11-04). Read it with this plan; the "How it works (decided)" section is binding.

## Review Focus

1. The hub dies mid-exchange (crash, restart, MQTT loss) → the room's music comes back within 30 s by the hold timeout, and the board's window closes by itself. Test `hold_expires_without_refresh` in Task 1.
2. nidoo-sound restarts mid-exchange → holds are not retained, so the music comes back at once; the hub, never told the reply finished, gives up after 60 s, releases and goes idle. Test `spoken_never_comes_gives_up` in Task 6.
3. Two satellites in the same room both hear "Hey Jarvis" → one exchange only (the second wake is ignored while the first room session is not idle), so a light is not toggled twice and only one board answers. Test `second_wake_in_the_same_room_is_ignored` in Task 6.
4. A false wake (TV, a word that sounds like it) with no speech after it → no assistant turn, no reply, hold released when the window ends. Test `no_speech_closes_silently` in Task 6.
5. A wake word heard while the house is still thinking or speaking (the board's own speaker, a second person) → ignored, the running exchange goes on unchanged. Test `wake_while_busy_is_ignored` in Task 6.

When a player stops being held (release or expiry) its music returns through `fade_in` over `FADE_FRAMES`, counted from the first chunk after the release. Holds are never persisted.

### Task 3: hub — voice packets, key, replay guard

**Files:**
- Create: `crates/nidoo/src/assist/stt/mod.rs` (only `pub mod packet; pub mod guard;` for now; `pub mod stt;` in `assist/mod.rs`), `crates/nidoo/src/assist/stt/packet.rs`, `crates/nidoo/src/assist/stt/guard.rs`, `docs/reference/voice-protocol.md`
- Modify: `crates/nidoo/Cargo.toml` (`hmac = "0.12"`)

**Interfaces:**
- Produces (pure, no I/O):
  - Layout, little-endian, every datagram: `0..2 "NV"`, `2 version = 1`, `3 type`, `4..16 sid` (12 lowercase hex ASCII), body, last 8 bytes = `HMAC-SHA256(key, all bytes before the tag)[..8]`.
  - Hub → board: `0x01 Hello { nonce: u64, hub_ctr: u64, hub: SocketAddrV4 }` (ip 4 bytes + port u16: where the board streams; never the datagram's source), `0x02 Stop { hub_ctr: u64, session: u32 }`, `0x03 Listen { hub_ctr: u64 }`.
  - Board → hub: `0x10 Wake { nonce: u64, session: u32, kind: WakeKind, listen_ctr: u64 }` (`kind` 0 = wake word, 1 = follow-up; `listen_ctr` = the Listen's `hub_ctr`, 0 for a wake word), `0x11 Audio { session: u32, seq: u32, samples: Vec<i16> }` (1..=640 samples), `0x12 End { session: u32 }` (the board closed the window itself).
  - `pub struct Key([u8; 32])` with `from_hex(&str) -> Option<Key>` (64 hex chars), `to_hex(&self) -> String`, `generate() -> Key` (`getrandom`).
  - `pub enum HubMsg { Hello{..}, Stop{..}, Listen{..} }`, `pub enum BoardMsg { Wake{..}, Audio{..}, End{..} }`, `pub enum WakeKind { WakeWord, FollowUp }`.
  - `pub fn encode_hub(key: &Key, sid: &str, msg: &HubMsg) -> Vec<u8>`, `pub fn decode_board(key: &Key, datagram: &[u8]) -> Result<(String, BoardMsg), PacketError>`, and for tests and the protocol doc `encode_board`, `decode_hub`.
  - `#[derive(Debug, PartialEq, Eq, thiserror::Error)] pub enum PacketError { Short, Magic, Version, Type, Length, Sid, Tag }` — the tag is checked first after the length (constant time, `Mac::verify_truncated_left`), so an unauthenticated datagram never reaches body parsing.
  - `guard.rs`: `pub struct ReplayGuard` per satellite: `note_hello(&mut self, nonce: u64)` keeps the last `RECENT_NONCES = 3`; `accept_wake(&mut self, nonce: u64, session: u32) -> bool` true only for a recent nonce and a session above every session already accepted under that nonce. `pub struct HubCounter` with `next(&mut self, unix_us: u64) -> u64` = `max(last + 1, unix_us)` (rises across hub restarts, so boards keep accepting).
